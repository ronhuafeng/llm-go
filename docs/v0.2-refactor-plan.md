# llmkit-go v0.2 Refactor Plan

Status: implemented, standalone/integration verified, and released as v0.2.0

Contract revision: `llmkit-v0.2-r3`

## Purpose

`llmkit-go` provides provider-neutral primitives for typed structured-output
calls, schema projection and validation, generic bounded stabilization, and
feedback-driven LLM retries.

It must not depend on a provider adapter or provider SDK. It must preserve
provider evidence without interpreting provider-specific facts.

## Verified Current Facts

The current repository has four public packages:

- `llmschema`: `SchemaJSONFor`, permissive `Decode`, and redundant
  `DecodeString`.
- `llmadapter`: `Caller`, `Request`, a `Response` containing only
  `FinalResponse`, `Value`, and an overlapping retry `Op` API.
- `settle`: `Op`, `Run`, and syntax-only `Bind`/`Runner`.
- `llmstep`: structured-output feedback retry, but attempts omit call results
  and errors.

`GOWORK=off go list ./...` currently resolves these packages without a provider
dependency. These facts must be rechecked before implementation.

## Ownership

`llmschema` owns Go type to JSON Schema projection and schema-enforced decode.

`llmadapter` owns one provider-neutral request/response call and typed decode of
that response.

`settle` owns generic bounded run/validate stabilization.

`llmstep` owns prompt rendering, structured calls, typed validation feedback,
feedback sanitization, and bounded retry audit history.

No package owns provider transport, provider policy, generic workflow, raw
metadata bags, or provider-neutral streaming.

## Target Handwritten Public API

This section is normative. Declarations not listed here are either documented
legacy exports during their deprecation window or should not be public.

### llmschema

```go
package llmschema

type Violation struct {
	Path    string
	Keyword string
	Message string
}

type SchemaValidationError struct {
	Violations []Violation
}

func (e *SchemaValidationError) Error() string

func SchemaJSONFor[T any]() (json.RawMessage, error)
func Decode[T any](data []byte) (T, error)
```

`Decode` validates the JSON against `SchemaJSONFor[T]` before unmarshalling.
Violations are stable, ordered, and do not retain raw model output.
`DecodeString` is deprecated in v0.2 and removed no earlier than v0.3.

```go
package llmadapter

var (
	ErrNilCaller                error
	ErrEmptyResponse            error
	ErrProviderIdentityMismatch error
)

type ValueStage string

const (
	ValueStageRequest ValueStage = "request"
	ValueStageCall    ValueStage = "call"
	ValueStageDecode  ValueStage = "decode"
)

type ValueError struct {
	Stage ValueStage
	Err   error
}

func (e *ValueError) Error() string
func (e *ValueError) Unwrap() error

type ValueResult[T any] struct {
	Value    T
	Response Response
}

func RequestFor[T any](prompt string) (Request, error)
func Value[T any](ctx context.Context, caller Caller, prompt string) (T, error)
func ValueDetailed[T any](ctx context.Context, caller Caller, prompt string) (ValueResult[T], error)
```

`ValueDetailed` is the implementation core. `Value` returns its value and the
same error. Every non-nil error returned by `ValueDetailed` is a `ValueError`:
an error generating the typed request schema has `ValueStageRequest`; an error
from `Caller.Call`, including a partial provider failure, has `ValueStageCall`;
an error decoding a successful call has `ValueStageDecode`. The populated
response is preserved for call and decode failures. `llmstep` maps this explicit
stage and never infers it from whether response fields are zero.

`Usage == nil` means the provider did not report usage. A non-nil all-zero value
means the provider explicitly reported zero values. Provider details must be a
typed immutable value; `map[string]any` and raw JSON are not accepted substitutes.

When `ProviderDetails` is non-nil,
`Execution.ProviderName == ProviderDetails.ProviderName()` is required.
`ValueDetailed` checks the invariant for successful and partial call responses.
A mismatch is wrapped as `ValueStageCall` with
`ErrProviderIdentityMismatch`. If `Caller.Call` also returned an error, the
`ValueError` retains both causes with `errors.Join`; identity validation never
replaces the provider failure. Provider adapters must also cover the invariant
with contract tests.

`Options`, `Op`, and `NewOp` are deprecated in v0.2 and removed no earlier than
v0.3.

### settle

```go
package settle

var (
	ErrInvalidMaxIter error
	ErrNilOp          error
	ErrUnsettled      error
)

type Op[I, O any] interface {
	Run(context.Context, I) (O, error)
	Validate(context.Context, I, O) (bool, error)
}

type Stage string

const (
	StageRun      Stage = "run"
	StageValidate Stage = "validate"
)

type Attempt[O any] struct {
	Iteration int
	Output    O
	HasOutput bool
	Settled   bool
	Stage     Stage
	Err       error
}

type Result[O any] struct {
	Output    O
	HasOutput bool
	Attempts  []Attempt[O]
}

func Run[I, O any](ctx context.Context, op Op[I, O], input I, maxIter int) (O, error)
func RunDetailed[I, O any](ctx context.Context, op Op[I, O], input I, maxIter int) (Result[O], error)
```

`Op.Run` returning nil error means it successfully produced a candidate and
sets `HasOutput=true`. `Op.Run` returning an error means no candidate was
produced: its `O` is ignored, `HasOutput=false`, and the attempt records
`StageRun`. A validation error preserves the successfully produced candidate
and records `StageValidate`. A non-error validation rejection records the
candidate with `Settled=false` and no failure stage.

`RunDetailed` preserves every successfully produced candidate. Exhaustion
returns `ErrUnsettled` with the last candidate and complete attempt history.
`Run` returns the detailed output and the same error. The generic contract does
not support partial output plus a run error; add no `Candidate[O]` abstraction
without a proven consumer. `Bind` and `Runner` are deprecated in v0.2 and
removed no earlier than v0.3.

### llmstep

```go
package llmstep

var (
	ErrNilRender      error
	ErrUnsafeFeedback error
)

type Feedback struct {
	Iteration int
	Summary   string
	Codes     []string
	Locations []string
}

type ValidationResult struct {
	Settled  bool
	Feedback []Feedback
}

type FeedbackSanitizer func([]Feedback) ([]Feedback, error)

type Step[I, O any] struct {
	Caller    llmadapter.Caller
	Render    func(context.Context, I, []Feedback) (string, error)
	Validate  func(context.Context, I, O) (ValidationResult, error)
	MaxIter   int
	Sanitizer FeedbackSanitizer
}

type Stage string

const (
	StageRender   Stage = "render"
	StageRequest  Stage = "request"
	StageCall     Stage = "call"
	StageDecode   Stage = "decode"
	StageValidate Stage = "validate"
	StageSanitize Stage = "sanitize"
)

type StepError struct {
	Stage     Stage
	Iteration int
	Err       error
}

func (e *StepError) Error() string
func (e *StepError) Unwrap() error

type Attempt[O any] struct {
	Iteration  int
	Feedback   []Feedback
	Call       llmadapter.ValueResult[O]
	Validation ValidationResult
	Err        error
}

type Result[O any] struct {
	Output    O
	HasOutput bool
	Attempts  []Attempt[O]
}

func Run[I, O any](ctx context.Context, step Step[I, O], input I) (O, error)
func RunDetailed[I, O any](ctx context.Context, step Step[I, O], input I) (Result[O], error)
func StrictFeedbackSanitizer([]Feedback) ([]Feedback, error)
```

Each attempt is appended before returning a stage error. `Attempt.Err` and the
returned `StepError` share the same cause chain. Fields for stages that did not
run remain zero. Rendered prompts and raw model output are not retained by
default.

`llmstep` obtains request/call/decode stage only by using `errors.As` to extract
a `*ValueError`, then maps each `ValueStage` to its corresponding `Stage`. It
does not inspect response emptiness or provider details to guess the stage.

## Error And Snapshot Contract

- Errors support `errors.Is`/`errors.As` and retain causes with `Unwrap`.
- Result and feedback slices are copied before publication.
- A typed nil `ProviderDetails` implementation is invalid.
- Non-nil provider details and neutral provider identity always agree.
- Simple APIs are projections of detailed APIs; they do not have separate call
  or retry implementations.

## Implementation Sequence

1. Add `llmadapter` detailed response/evidence types, explicit value stages,
   provider identity checks, and projection tests.
2. Make `llmschema.Decode` validate generated schemas and add typed violations.
3. Add `settle.RunDetailed`; preserve latest output and history on all failures.
4. Change unreleased `llmstep` attempts to generic evidence-preserving attempts.
5. Add deprecations and migration docs; do not remove published legacy APIs
   before their documented version.
6. Add a handwritten export allowlist architecture test using canonical
   `go/types` signatures. Generated/test/internal declarations are excluded.

## Required Tests

- Schema required/additional/nested/nullable/scalar/list/map constraints.
- Response preservation on decode failure.
- Provider name/details agreement, mismatch failure, and immutable snapshots.
- Call-stage partial response and decode-stage response preservation.
- `Value`/`ValueDetailed`, `Run`/`RunDetailed` projection equivalence.
- Every settle and llmstep failure stage with partial evidence.
- Architecture dependency direction and handwritten export allowlist.
- Compile-only downstream fake caller implementing the mirrored contract.
