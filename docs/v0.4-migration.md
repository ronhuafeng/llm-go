# Migrating to v0.4

`llmstep.Attempt.Validation` and `llmstep.Attempt.RetryFeedback` now publish two
different facts:

- `Validation` is the validator decision exactly as returned, including
  nil-versus-empty slice shape. It is not rewritten by the sanitizer.
- `RetryFeedback` is the sanitizer-owned, iteration-stamped feedback eligible
  for the next `Render` call. The following attempt's `Feedback` is a snapshot
  of this value.

Code that previously treated `Attempt.Validation.Feedback` as sanitized model
feedback must read `Attempt.RetryFeedback` instead. Code auditing the validator
decision should continue to read `Attempt.Validation` and can now distinguish
it from the model-facing projection.

Sanitization is not retrospective redaction of detailed validation evidence.
Applications handling secrets, private URLs, personal data, or other sensitive
facts must redact, omit, or deliberately pseudonymize those facts before the
validator returns them. A custom sanitizer controls only `RetryFeedback` and
what reaches the next model render.
