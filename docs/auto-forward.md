# Auto-forward integration

Auto-forward owns bounded convergence and integration of a completed native
proposal. The final main update is always a normal non-force fast-forward of
the exact accepted PR head H. [`verify.md`](verify.md) owns the unchanged four
required checks and existing review policy.

## Trusted handoff

The reusable workflow accepts PR number, expected H, immutable original base B,
last certified verification base, fixed upstream ref/kind/SHA U, and the original
absolute deadline. The upstream caller marks its successfully completed proposal
Ready using publication authority, then hands off once. That caller-side
completion/readiness implementation is supplied by companion PR #456; the
reusable integration interface alone does not make an incomplete goal eligible. The old dispatcher
excludes native `-goal-` branches. Manual PR-number dispatch remains the reviewed
route. It binds exact H and entry main B. Ordinary-code proposals may undergo
conflict-free mechanical reconciliation for SDK root/protocolv2/wirejson and llmkit/llmcaller Go
changes and inert Markdown docs, with immutable B/current-M runtime
proof and fresh four-check CI, without a provider or inferred U. Other runtime/control paths and generic semantic
conflicts remain blocked because no fixed repair objective was authorized.
Same-H reviewed manual FF retains its existing behavior; reconstructed generic
candidates that alter protected gate/control authority are conservatively blocked.

The trusted default-branch controller reads Git refs and PR identity, checks the
publication App creator and the actual bound publication/integration App writer,
and rejects external edits. Observed main M must descend from the last observed
M and the certified handoff base. A reset or divergent rollback blocks. Fixed U
cannot move; a newer accepted baseline supersedes the proposal rather than
causing a downgrade. Stable-baseline policy is shared with native goals.

## Repeated bounded reconciliation

All work shares the original finite deadline, including queue/setup time. Each
new M/H pair needs immutable original-B and current-M contract verification.
This also applies when M is already an ancestor of unchanged H: stale proof is
not renewed by ordinary CI alone, and no new commit is needed in that case.

For divergence, an isolated clone first attempts a conflict-free linear rebase.
A clean rebase with a complete local assertion failure also enters fresh
semantic repair; incomplete/setup/compilation/timeout and CI failures remain
blockers. If Git conflicts remain, the complete candidate delta is applied to M and a fresh
native repair invocation starts; it never resumes an archived/completed goal.
The existing verification tool supplies diagnostics and accepts only an unchanged
verified snapshot. An unchanged failing repair stops. No automatic ours/theirs,
merge commits, dropped assertions, or verifier weakening is permitted.

Native integration and reconstructed generic candidates additionally preserve current-M gate authority: complete CI,
controller, security, verifier/generator package trees and all Go module/workspace
metadata cannot be changed by the proposed H. This includes newly added files.
Proposals requiring such changes need explicit reviewed manual integration.
Production SDK/schema adaptations remain eligible.

A changed H is published only with `--force-with-lease=refs/heads/branch:oldH`.
The branch writer is the scoped integration App. Its four fresh exact-head CI
results must then succeed via the existing `checkacceptance` policy. Pending
checks wait within the same deadline; failure/cancellation stops without replay.
Review, identity, ancestry, proof and checks are reobserved before main's normal
non-force push. A trusted host-only pre-push hook binds the server-advertised
main OID to proved M and permits exactly the intended H/main update; Git server
compare-and-swap protects later movement. Main movement repeats reconciliation under the same deadline.
Lost responses are read back; unknown outcomes and external head edits stop.

After main contains H, deletion requires GitHub to report this PR merged, the
branch still to equal H, and no other open PR to use it. Deletion itself is
lease-bound and read back. Duplicate completion does not repeat integration.

## Credential boundary

Prewarming upstream inputs and installing the official runtime happen before
App/provider credentials enter the trusted controller. Existing GoalSandbox
uses an explicit environment allowlist, private PID/proc/root and bounded mounts;
only provider credentials enter the fresh model runtime. Oracle verification
uses the existing credential-free sandbox. No App key/token, host environment,
private file, extra descriptor or filesystem socket is mounted into either.
Initial identity discovery uses only a repository-read token; write tokens exist
only around individual effects. Provider networking remains available; therefore no repository credential broker
may be exposed on host TCP or abstract sockets.

The trusted host alone owns `AUTO_FORWARD_APP_PRIVATE_KEY` and mints/revokes a
repository-scoped token around each effect. The final exact-existing-H
fast-forward requests Contents write only. Publishing a newly created or
rewritten candidate with workflow changes still requests existing Workflows write.
GitHub rejection remains a blocker; the controller grants nothing. Token failures
report only a bounded category and numeric HTTP status when available, without
response bodies or a claim that every failure means a missing App grant.
Provider secrets are explicitly mapped, never inherited wholesale. Safe verifier
diagnostics remain separate from private runtime state and raw transcripts.

## Evidence and deployment

Git fixture/race tests cover reconciliation, leases, lost responses, current-head
checks and isolation boundaries. Existing live failures/missing/cancelled checks
remain blockers. Local source tests are not evidence of a production main write.
Hosted sandbox/live execution and a real deployed reconciliation/repair/main
readback require normal CI and separately authorized integration acceptance.
No policy change authorizes bypassing its own checks or merging its own PR.
