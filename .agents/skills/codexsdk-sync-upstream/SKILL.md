# Codex SDK upstream repair

Use this skill only after native planning returns a concrete
`semantic_unresolved` result for an already selected/generated target.
It is not a general implementation, live-test, publication, or integration skill.

## Your outcome

Make the smallest handwritten owner-local change that permits lossless
representation of the supplied candidate. Add focused tests. Leave all changes
unstaged and uncommitted.

Read the supplied target, candidate, stage/path, and failure reason, then inspect
only affected source/tests. Before selecting files, read
`codexsdk/internal/protocolsync/changes.go`; its `isAgentProposalPath` owns the
allowed scope. Do not infer permission from an error's wording or file name.

Do not hand-edit generated schema/types/facades. The workflow owns exact target
selection, first Plan, re-plan of the same retained candidate, Apply after a
ready plan, deterministic checks, and publication authorization. Focused local
checks may help, but a final Agent message does not certify success.

## Stop boundaries

Stop with evidence when the needed change alters product intent, changes
control policy, or falls outside the allowed handwritten scope. Report
`needs-maintainer` rather than changing the target, enlarging permissions, or
weakening acceptance.

Do not configure Git/GitHub authentication; stage, commit, push, mutate PRs,
dispatch workflows, integrate, or tag. Do not inherit repository-write
credentials or change unrelated runtime behavior.

## Protocol proof versus live acceptance

[`Protocol synchronization`](../../../docs/protocol-sync.md) owns construction
and publication. [`Verification`](../../../docs/verify.md) owns final PR
acceptance. The accepted [live integration design](../../../docs/live-codex.md)
uses an installed official Codex release and a real model in separate scenarios;
its implementation transition is recorded there.

Do not change the live fixture's model/runtime selection, retire scenarios, or
weaken live assertions to make a protocol repair pass. A live failure is not
authority for this skill to edit repository acceptance controls. Keep the
protocol Agent's own execution settings separate from the live-suite fixture.
