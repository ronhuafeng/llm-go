# Migrating to v0.5

`llmstep` now sanitizes validation feedback only when a subsequent retry will
actually render it.

Previously, an unsettled final attempt still invoked the configured feedback
sanitizer. Unsafe terminal feedback could therefore replace the exhaustion
error with a sanitize-stage `llmstep.StepError`, even though no model-facing
retry was possible. It could also populate `Attempt.RetryFeedback` despite
there being no next render.

Starting with v0.5, the final allowed unsettled attempt:

- preserves the validator decision in `Attempt.Validation`;
- leaves `Attempt.RetryFeedback` nil;
- does not invoke `Step.Sanitizer`; and
- returns an error wrapping `settle.ErrUnsettled`.

Sanitizer errors on non-final unsettled attempts are unchanged: when another
attempt would run, rejected feedback still returns a `llmstep.StepError` with
`StageSanitize`, and the original validator decision remains available in the
detailed result.

Callers that classified terminal failures by `llmstep.StageSanitize` should
instead use `errors.Is(err, settle.ErrUnsettled)` when the retry budget is
exhausted. Treat `Attempt.RetryFeedback` as evidence that a real next render
was available, not as an audit result for the terminal validation decision.
