# Migrating to llmkit v0.7.0

The default `llmstep.StrictFeedbackSanitizer` no longer accepts free-form
`Feedback.Summary` values. Previously, short summaries that did not match a
small set of sensitive-looking patterns could be sent to the next model render.
Those patterns could not provide a reliable confidentiality boundary.

When `Step.Sanitizer` is nil, a non-empty summary on an attempt that can retry
now returns a sanitize-stage error wrapping `llmstep.ErrUnsafeFeedback`. The
default continues to accept identifier-oriented `Codes` and `Locations`. Final
unsettled attempts remain unchanged: because no retry will render their feedback,
they do not invoke the sanitizer.

Applications that used default summaries must either replace them with
already-redacted classification codes and abstract locations, or configure an
explicit custom sanitizer that produces the intended model-facing text. A
custom sanitizer owns that disclosure decision; it must not copy validator
evidence blindly.

`Attempt.Validation` remains the exact validator-owned decision and is not
retrospectively redacted. Neither the default nor a custom sanitizer is DLP,
secret scanning, or a privacy guarantee. Applications must still redact or omit
credentials, personal information, private source, customer identifiers, and
other sensitive values before returning validation evidence unless retaining
them is explicitly intended.
